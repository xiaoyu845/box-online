# 自动挂在线（Box Online）

一个 Windows 桌面面板：**同时把多个游戏账号挂在线上**。
自动登录、自动进服、保持在线、到点领在线奖励、领完自动换下一个角色。

| 平台 | Python | 组成 |
|---|---|---|
| Windows 10/11 x64 | 3.13 | 面板 + 调度层 |

> **本版本范围（重要）**
> 这是**最初版本**：只包含面板、账号库、导入、登录节流、槽位调度、循环挂角、
> 在线奖励与执行体接口。
> **与游戏登录／进服相关的对接不在本版本内，留作后续开发**（`bridge.py`、
> `mc_bot.py`、`mc_client.py` 为接口骨架，调用会提示"尚未实现"）。
> 因此本版本可以浏览、编译、运行界面与账号管理，但**不能真正进服挂机**。

> **范围声明**：本仓库只包含**面板与调度层**。
> 登录与进服能力来自第三方开源项目（见[致谢](#致谢)），
> 本仓库**不包含**、也**不解说**它们的实现原理。

---

## 它解决什么问题

多账号挂机真正麻烦的不是"挂"，而是这四件事：

1. **反复登录** —— 每开一个号就登一次，十几个一起上必然被限流
2. **验证码随机卡住** —— 某个号忽然要验证码，整个流程停在那儿
3. **挂了不知道有没有真挂** —— 进程在跑，但没进服 / 被踢了 / 永远不换角
4. **账号库是唯一不可再生的东西** —— 一旦写坏，号就没了

这个面板就是围绕这四点做的。

## 功能

**账号库**
- 三种导入：文件（CSV/Excel）、粘贴、手动
- 登录方式支持：账号密码 / 官方渠道（邮箱、手机）/ 直接凭据
- 原子写、缩水拒写、逐条容错、残渣抢救——任何异常都不会变成"保存一个更小的库"
- 空号可见（`⚠ 无角色`），并可批量**检测角色 / 创建角色**

**凭据复用（省限流的关键）**
- 把"每次进服都密码登录"变成"登录一次、长期复用"
- 支持单个转换、批量更新、整体预热
- 失效自动回退密码登录，并把原因写进账号库（可见、可排查）

**调度与挂机**
- 槽位矩阵：每位一张卡（谁、什么角色、挂多久、什么状态）
- 预留两种执行方式（**轻量执行体，每账号约 75MB 基线** / 真实客户端），执行体实现留待后续
- **循环挂角**：满门槛 → 领齐 4 阶段 → 关连接 → 换下一个角色
- 同一账号只占一个挂机位（避免自己把自己踢下线）

**可观测**
- 运行日志、在线时长、奖励进度（4 阶段 + 4 里程碑）

## 快速开始

```powershell
# 1) 依赖
py -3 -m pip install -r requirements.txt

# 2) 启动（先确保外部进服组件已在运行）
py -3 run.py
```

界面出来后：

1. **账号库** → 导入账号
2. 选中账号 → **转凭据**（或「一键更新」/「预热全部」）
   需要图片验证码时在弹窗里照着填
3. 回主界面 → **开始挂机**，窗口数**先从 3~4 个**起步

> **打包版**请用运行目录里的**启动器**启动，不要直接双击 exe——
> 直接双击会让"数据落在哪"变得不确定。

完整流程、每一步的验收标准、9 条排障，见 **[docs/自动挂在线.md](docs/自动挂在线.md)**。

## 文件说明

按职责分组。**先看标 ★ 的四个**，就能理解这套东西怎么运转。

### ★ 账号与登录

| 文件 | 作用 |
|---|---|
| `accounts.py` | **账号库**：存储、并发加锁、原子写、缩水拒写、逐条容错加载 |
| `importer.py` | 批量导入：文本 / CSV / Excel，解析、去重、体检 |
| `sauth.py` | **凭据转换与校验**（含内置 4399 登录客户端） |
| `gate.py` | 登录节流：短退避重试，不做全局冷却 |

### ★ 调度与挂机

| 文件 | 作用 |
|---|---|
| `scheduler.py` | **槽位调度**：谁在哪个位、登录编排、会话复用、同账号单槽 |
| `char_loop.py` | **循环挂角**：满足在线门槛 → 领奖 → 换下一个角色 |
| `states.py` | 槽位状态定义 |
| `procutil.py` | 进程与路径工具（进程清理、路径判定） |

### 在线奖励

| 文件 | 作用 |
|---|---|
| `claim.py` | 奖励判定：阶段 + 里程碑，**以服务端返回为准** |
| `online_console.py` | 领奖台界面（进度、可领、倒计时） |

### 界面

| 文件 | 作用 |
|---|---|
| `ui_main.py` | 主面板：账号库、槽位矩阵、运行日志 |
| `warmup.py` | 预热：批量过一遍账号，收集需要验证码的 |
| `win_embed.py` | 游戏窗口嵌入与缩放 |

### 基础设施

| 文件 | 作用 |
|---|---|
| `paths.py` | 路径与配置；数据目录**按内容识别**，不依赖固定目录名 |
| `run.py` | 开发入口（`py -3 run.py`） |
| `box_online_entry.py` | 打包入口（供 PyInstaller 使用） |

### 后续开发（接口已留，当前为空实现）

| 文件 | 应实现什么 |
|---|---|
| `bridge.py` | 进服对接层：登录 → 会话 → 选服 → 选角 → 为挂机位准备连接入口 |
| `mc_bot.py` | 执行体-轻量：进世界 → 走到坐标 → 保持在线 → 领奖 |
| `mc_client.py` | 执行体-真实客户端，以及实例目录 / 命令文件工具 |

> 这三个模块在本版本只会抛「尚未实现」，调用链其余部分都已就绪，
> 按接口补上实现即可跑通。

## 已知行为（不是 bug）

| 现象 | 原因 |
|---|---|
| 十几个位同时开，全卡在"登录中" | 撞上登录频率限制，只能排队；**先把账号转成凭据** |
| 提示"稍后再试" | 频率限制，几秒就恢复，**不是封号** |

## 边界与免责

**本项目不做**：伪造登录标识、更换网络身份来规避服务端判定、绕验证码、注册环节的伪造实名。

**使用风险自负**：自动化挂机可能违反游戏的服务条款；账号可能被封。
请只用于你拥有或获授权使用的账号，并自行承担后果。

**做不到的**：同一账号的并发连接（服务端按账号判定，客户端侧绕不过）。
