# 自动挂在线（Box Online）

一个 Windows 桌面面板：**同时把多个游戏账号挂在线上**。
自动登录、自动进服、保持在线、到点领在线奖励、领完自动换下一个角色。

| 平台 | Python | Node | 许可 |
|---|---|---|---|
| Windows 10/11 x64 | 3.13 | 18+（协议执行体） | 未指定 |

---

## 开源范围

### ✅ 已开源（本仓库包含完整实现）

| 模块 | 内容 |
|---|---|
| **账号库** | `accounts.py` — 原子写、缩水拒写、逐条容错加载、并发加锁 |
| **批量导入** | `importer.py` — 文本 / CSV / Excel，解析、去重、体检 |
| **凭据** | `sauth.py` + `_vendor/n4399.py` — 4399 登录客户端、凭据转换与校验 |
| **登录节流** | `gate.py` — 短退避重试，不做全局冷却 |
| **槽位调度** | `scheduler.py` — 登录编排、会话复用、同账号单槽 |
| **循环挂角** | `char_loop.py` — 满门槛 → 领奖 → 换下一个角色 |
| **在线奖励** | `claim.py` / `online_console.py` — 阶段与里程碑判定、领奖台 |
| **界面** | `ui_main.py` / `online_console.py` / `warmup.py` / `win_embed.py` |
| **协议执行体** | `mc_bot.py` + `mf_bot/` — **进服 → 寻路 → 保持在线 → 定时领奖** |
| **文档** | `docs/` — 使用与部署两篇 |

### 🚧 未开源（只留接口，留作后续）

| 模块 | 原本负责什么 | 现在的状态 |
|---|---|---|
| `bridge.py` | 登录、会话管理、选服、选角、为挂机位准备连接入口 | 接口骨架，调用抛「尚未实现」 |
| `mc_client.py` | 真实客户端执行体、实例目录与命令文件 | 同上 |

**这意味着**：本仓库的调度、账号库、界面、协议执行体都能读、能编译、能起界面，
但**按账号登录并拿到一个可连的连接入口**这一步没有开源——
所以开箱**不能直接进服**，需要自行接上这一层（接口签名已在 `bridge.py` 里写清）。

### ⚠️ 需要自行配置

| 位置 | 需要填什么 | 不填的后果 |
|---|---|---|
| `claim.py` 的 `PLUGIN_CHANNEL` | 服务端插件消息通道名 | 进服不受影响，**领奖会失败** |
| `mc_bot.py` 的 `DEFAULT_FORGE_MODS` | 目标服务端的模组列表 | 握手被服务端判为原版客户端并断开 |

## 它解决什么问题

多账号挂机真正麻烦的不是"挂"，而是这四件事：

1. **反复登录** —— 每开一个号就登一次，十几个一起上必然被限流
2. **验证码随机卡住** —— 某个号忽然要验证码，整个流程停在那儿
3. **挂了不知道有没有真挂** —— 进程在跑，但没进服 / 被踢了 / 永远不换角
4. **账号库是唯一不可再生的东西** —— 一旦写坏，号就没了

这个面板就是围绕这四点做的。

## 功能

**账号库**
- 三种导入：文件（CSV/Excel）、粘贴、手动
- 登录方式支持：账号密码 / 官方渠道（邮箱、手机）/ 直接凭据
- 原子写、缩水拒写、逐条容错、残渣抢救——任何异常都不会变成"保存一个更小的库"
- 空号可见（`⚠ 无角色`），并可批量**检测角色 / 创建角色**

**凭据复用（省限流的关键）**
- 把"每次进服都密码登录"变成"登录一次、长期复用"
- 支持单个转换、批量更新、整体预热；失效自动回退密码登录并记录原因

**调度与挂机**
- 槽位矩阵：每位一张卡（谁、什么角色、挂多久、什么状态）
- **协议执行体**（每账号约 75MB 基线）：进服、寻路、保持在线、定时领奖
- **循环挂角**：满门槛 → 领齐 4 阶段 → 关连接 → 换下一个角色
- 同一账号只占一个挂机位（避免自己把自己踢下线）

**可观测**
- 运行日志、在线时长、奖励进度（4 阶段 + 4 里程碑）

## 快速开始

```powershell
# 1) Python 依赖
py -3 -m pip install -r requirements.txt

# 2) 协议执行体依赖（Node）
cd mf_bot; npm install; cd ..

# 3) 起界面
py -3 run.py
```

界面能正常打开、账号库能导入导出，就说明跑通了。

> **要真正进服挂机**，还需要两件事（本仓库未包含）：
> ① 按 `bridge.py` 的接口接上"登录 + 建立连接入口"这一层；
> ② 填上 `claim.py` 的插件通道名与 `mc_bot.py` 的模组列表。
> 具体流程见 `docs/自动挂在线.md` 第三、四节。

## 文件说明

按职责分组。**先看标 ★ 的四个**，就能理解这套东西怎么运转。

### ★ 账号与登录

| 文件 | 作用 |
|---|---|
| `accounts.py` | **账号库**：存储、并发加锁、原子写、缩水拒写、逐条容错加载 |
| `importer.py` | 批量导入：文本 / CSV / Excel，解析、去重、体检 |
| `sauth.py` | **凭据转换与校验**（内含内置 4399 登录客户端） |
| `gate.py` | 登录节流：短退避重试，不做全局冷却 |

### ★ 调度与挂机

| 文件 | 作用 |
|---|---|
| `scheduler.py` | **槽位调度**：谁在哪个位、登录编排、会话复用、同账号单槽 |
| `char_loop.py` | **循环挂角**：满足在线门槛 → 领奖 → 换下一个角色 |
| `states.py` | 槽位状态定义 |
| `procutil.py` | 进程与路径工具（进程清理、路径判定） |

### 在线奖励

| 文件 | 作用 |
|---|---|
| `claim.py` | 奖励判定：阶段 + 里程碑，**以服务端返回为准** |
| `online_console.py` | 领奖台界面（进度、可领、倒计时） |

### 界面

| 文件 | 作用 |
|---|---|
| `ui_main.py` | 主面板：账号库、槽位矩阵、运行日志 |
| `warmup.py` | 预热：批量过一遍账号，收集需要验证码的 |
| `win_embed.py` | 游戏窗口嵌入与缩放 |

### 协议执行体（已开源）

| 文件 | 作用 |
|---|---|
| `mc_bot.py` | 起进程、传配置、收状态；订阅状态与奖励回传 |
| `mf_bot/bot.js` | Node + mineflayer：连服、握手、寻路、心跳、领奖 |
| `mf_bot/package.json` | 依赖声明（mineflayer / mineflayer-pathfinder） |

### 基础设施

| 文件 | 作用 |
|---|---|
| `paths.py` | 路径与配置；数据目录**按内容识别**，不依赖固定目录名 |
| `run.py` | 开发入口（`py -3 run.py`） |
| `box_online_entry.py` | 打包入口（供 PyInstaller 使用） |

### 🚧 未开源（接口骨架）

| 文件 | 应实现什么 |
|---|---|
| `bridge.py` | 进服对接层：登录 → 会话 → 选服 → 选角 → 为挂机位准备连接入口 |
| `mc_client.py` | 真实客户端执行体，以及实例目录 / 命令文件工具 |

## 已知行为（不是 bug）

| 现象 | 原因 |
|---|---|
| 十几个位同时开，全卡在"登录中" | 撞上登录频率限制，只能排队；**先把账号转成凭据** |
| 提示"稍后再试" | 频率限制，几秒就恢复，**不是封号** |
| 领奖没反应 | `claim.py` 的插件通道名尚未填写 |
| 进服被秒断 | 模组列表与服务端不一致（`DEFAULT_FORGE_MODS`） |

## 边界与免责

**本项目不做**：伪造登录标识、更换网络身份来规避服务端判定、绕验证码、注册环节的伪造实名。

**使用风险自负**：自动化挂机可能违反游戏的服务条款；账号可能被封。
请只用于你拥有或获授权使用的账号，并自行承担后果。

**做不到的**：同一账号的并发连接（服务端按账号判定，客户端侧绕不过）。
